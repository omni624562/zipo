# Zipo 的 UX／UI 設計方針

新增或修改介面時，依下列方針檢查。

## 1. 先做對最常見的事，進階選項往後放

- 九成的使用者只是「壓縮」和「解壓縮」，預設值要能直接按下去。
- 少用的選項收進「更多選項」，不和主要選項並排。
- 預設壓縮格式是 zip（Windows、macOS 不必安裝軟體就能開啟）；記住使用者上次的選擇。

## 2. 用使用者的語言，不用工程術語

- 以結果描述選項，而不是機制。例如「保留資料夾結構／所有檔案放在同一層」，不寫「完整路徑／不含路徑」。
- 錯誤訊息包含三件事：發生什麼事、為什麼、下一步怎麼做。
  例：「磁碟空間不足：需要 2.1 GB，目前可用 800 MB。請清出空間，或改解壓縮到其他磁碟。」

## 3. 按鈕寫出會發生的動作

- 主要按鈕用動詞寫出結果，例如「壓縮」「解壓縮」，而不是「確定」。
- 只是告知、沒有後續動作的訊息才用「確定」。

## 4. 最重要的資訊不可以被截斷

- 路徑太長時保留結尾（檔名、目的資料夾），從中間省略；滑過時顯示完整內容。
- 名稱類的文字以「…」截斷時，要能看到完整內容（滑過提示或欄位加寬）。

## 5. 每個動作都有回饋，久的動作要能取消

- 0.1 秒內要有反應。
- 超過 1 秒顯示進度；可能超過幾秒的工作要能取消，取消後不留下暫存檔。
- 完成時提供下一步（例如「開啟資料夾」）。

## 6. 不讓使用者在不知情下失去資料

- 預設值是安全的（同名檔案預設「每次詢問」）。
- 不可逆的動作要確認，確認按鈕用紅色並寫明動作。
- 有疑慮時保留檔案（例如有項目被略過，就不把壓縮檔移到資源回收筒）。

## 7. 和 Windows、檔案總管的習慣一致

| 操作 | 按鍵 |
|---|---|
| 開啟 | Enter、按兩下 |
| 上一層 | Alt+↑、Backspace |
| 上一頁／下一頁 | Alt+←／Alt+→ |
| 全選 | Ctrl+A |
| 延伸選取 | Shift+↑／↓／Home／End、Shift+按一下 |
| 加選 | Ctrl+按一下 |
| 搜尋 | Ctrl+F、F3 |
| 網址列 | Ctrl+L、Alt+D |
| 重新整理 | F5 |
| 刪除（壓縮檔內） | Delete |
| 預覽窗格 | Alt+P |

- 點整個欄位標題就能排序；多選、拖曳進出、右鍵選單的行為與檔案總管相同。
- 在檔案總管選取多個項目執行右鍵選單時，合併成一個視窗處理。

## 8. 鍵盤與輔助使用

- 所有功能都能只用鍵盤完成：Enter 確認、Esc 取消、Tab 可移到每個控制項。
- 文字對比至少 4.5:1（淺色與深色模式都要檢查）；停用的控制項與裝飾符號除外。
- 不只用顏色傳達資訊：成功或錯誤除了顏色，還要有圖示或文字。

## 9. 一致性

- 同一個概念用同一個詞；同類對話框的版面、按鈕位置、間距一致。
- 中文介面使用台灣用語；英文介面不可出現中文（有測試檢查）。

## 檢查清單

- [ ] 預設值不必修改就能完成最常見的用途
- [ ] 沒有工程術語；錯誤訊息有說明下一步
- [ ] 主要按鈕寫出動作
- [ ] 長路徑、長名稱看得到重要的部分
- [ ] 久的工作有進度、可以取消
- [ ] 會刪除或覆寫的動作有確認，預設值安全
- [ ] 鍵盤可以完成，淺色、深色模式都清楚
- [ ] 中英文介面都檢查過
